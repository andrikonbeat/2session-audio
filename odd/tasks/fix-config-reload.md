# Feature: fix-config-reload

## Objective
Make the generated `~/.config/dual-session-setup.conf` loadable again, so a
second run of the setup does not abort.

## Problem
`ensure_config` (in `lib/common.sh`) wrote every value unquoted:

```
MIXER_CONTROLS=$MIXER_CONTROLS   ->   MIXER_CONTROLS=Master PCM Front
```

`load_config` sources the config. On the next run bash parsed
`MIXER_CONTROLS=Master` as an assignment and then tried to execute `PCM` as a
command:

```
~/.config/dual-session-setup.conf: línea 13: PCM: orden no encontrada
ERROR: Config no válido: ~/.config/dual-session-setup.conf
```

Only the **second** run failed: the first run creates the config and never
re-reads it, so the bug was latent until re-running.

## Why
Reported by the user when re-running the one-command install right after the
dmix-slave fix.

## Scope (authorized)
- Quote string values when writing the config.
- Repair the existing config on this machine.
- Regression test that runs `setup.sh` twice.
- Ship to `origin/main`.

## Constraints
- No new deps; same no-root model. User-facing output in Spanish, code in English.

- The smoke suite fails if a generated value is left unquoted and breaks reload.
